# Руководство пользователя — Метрика

## Быстрое размещение

В панели сканера выберите **«Товар + ячейка (+1 шт.)»**. Отсканируйте код товара и код ячейки **в любом порядке**. Метрика добавит одну штуку в остаток и запишет операцию.

Для приёмки другого количества используйте режим оприходования с явным количеством. Перемещение — из карточки товара или перетаскиванием на карте хранения.

## Поиск в каталоге

| Префикс | Пример | Результат |
| --- | --- | --- |
| `#` | `#460123` | Штрихкод |
| `@` | `@контроллер` | Название |
| `!` | `!кабель` | Категория |
| `=` | `=стеллаж A` | Товары в найденной ячейке |
| `<` | `<10` | Остаток меньше N |

В карточке товара: распределение по ячейкам, приход/расход/перемещение, печать этикеток.

## Заказ на сборку

1. Создайте заказ: изделие, тираж, срок, приоритет.  
2. Добавьте компоненты (кол-во на одно изделие).  
3. **Зарезервировать** — проверка свободных остатков и закрепление по ячейкам.  
4. В разделе **ТСД** отсканируйте комплектацию.  
5. **Списать комплект**, затем **Завершить** после фактической сборки.

Зарезервированный товар недоступен для обычного расхода/перемещения. Чтобы править спецификацию — снимите резерв и верните заказ в черновик.

## Импорт CSV

Раздел **Товары → Импорт CSV**. Перед записью — предпросмотр.

| Столбец | Обязательный | Назначение |
| --- | --- | --- |
| `Штрихкод` / `barcode` | Да | Основной уникальный код |
| `Название` / `name` | Да | Имя товара |
| `Артикул` / `sku` | Нет | Артикул |
| `Категория` / `category` | Нет | Категория (создаётся при необходимости) |
| `Минимум` / `min_stock` | Нет | Минимальный остаток |
| `Количество` / `quantity` | Нет | Начальный остаток |
| `Ячейка` / `Адрес` / `location_barcode` | Нет | Штрихкод ячейки для начального остатка |

Пример (`;`):

```csv
Штрихкод;Название;Артикул;Категория;Минимум;Количество;Ячейка
4601234567890;Контроллер ESP32;MCU-0101;Контроллер;3;12;A-01-01
4601234567891;Кабель Dupont;CAB-0102;Кабель;10;50;A-01-02
```

Строки с уже существующим штрихкодом пропускаются; остальные обрабатываются.

## Пополнение и ABC

В **Пополнении** задайте срок поставки и страховой запас. Расчёт опирается на средний расход за 90 дней и резервы проектов. План можно выгрузить в CSV.

ABC-анализ — за 30 / 90 / 180 / 365 дней: классы A/B/C, средний расход в день, ориентировочное покрытие запасом.

## Ревизия

Обход ячеек с фиксацией факта. Расхождения можно скорректировать пакетно — в истории останется след операции.

## Резервные копии

**Настройки → экспорт/импорт** полной SQLite-базы (товары, адреса, остатки, операции, проекты, резервы, сканы…).

Перед импортом текущая база копируется в `backups`. Импорт **заменяет** текущие данные содержимым файла.

## Расширенный контур (0.5)

В сборке 0.5 доступны дополнительные рабочие места (организации, сотрудники, документы, CRM, клиентский контур, внутренний ЭДО). Это **локальный** контур учёта и коммуникаций:

- не заменяет внешнего оператора ЭДО / УКЭП;
- удалённый доступ с другого устройства требует отдельного серверного контура (в «домашней» поставке по умолчанию не включён).

Основной складской сценарий (каталог → ячейки → сканер → сборка) работает независимо.
